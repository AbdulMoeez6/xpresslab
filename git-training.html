First Step in Collaboration

What is this "Git" Thing Anyway?

Hello! Welcome to your first training. You might hear people talk about "Git" and "GitHub" when working on projects here at XpressLab. It might sound complicated, but the main idea is simple!

Imagine you're writing a story or drawing a picture. What happens if you make a mistake and want to go back to how it looked yesterday? Or what if you want to try adding a new character, but you're not sure if it will work out, so you want to keep the original safe?

Git is like a super-smart "Save" button for your computer work. It doesn't just save the latest version; it remembers all the different versions you've saved along the way. It's like having a time machine for your project!

Why Do We Need This Time Machine?

Using Git helps solve two big problems when working on computer projects, especially with other people:

Going Back in Time

Sometimes you change something, and it breaks everything! Without Git, it might be hard to remember exactly what you changed or get back to a version that worked. Git lets you easily rewind your project to an earlier saved point.

Working Together Nicely

Imagine you and a friend are both editing the same document at the same time. You might accidentally delete each other's work! Git allows everyone to work on their own copyof the project safely. Later, Git helps carefully combine everyone's changes together.

Key Ideas in Git (Simple Words)

You'll hear some special words used with Git. Don't worry about memorizing them perfectly right now, just get the basic idea:

Repository (or "Repo")

This is simply the main folder for your project where Git keeps track of everything. Think of it as the special project box that Git is watching.

Commit

This is the act of saving a snapshot of your work at a particular moment. When you "commit," you also write a short note (a "commit message") explaining what you changed (like "Fixed spelling mistake" or "Added a new paragraph"). It’s like taking a photo of your work and writing a label on the back.

Branch

Imagine you want to try a new idea, but you don't want to mess up your main work yet. A "branch" is like creating a separate copy or timeline of your project where you can experiment freely. If the idea works, you can merge it back later. If it doesn't, you can just ignore that copy.

Merge

This means combining the changes from one of your separate copies (a branch) back into your main project version. Git helps you do this carefully.

How Does This Connect to GitHub & XpressLab?

So, Git is the tool that tracks changes. GitHub (which we'll cover in the next training) is a website where you can store your Git project folders (repositories) online. It makes it easy to share your work and collaborate with others.

XpressLab uses projects stored on GitHub. When you follow our Project Guide, you'll be using these Git ideas (like making a copy called a "Fork", saving changes with "Commit", and sending your work for review with a "Pull Request").

This training helps you understand why you're clicking those buttons later!
